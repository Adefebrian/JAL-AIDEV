# JAL Core blocks

Page-level block specs: the sections a JAL page is assembled from. A block composes the component specs in `components.md`; it never re-specifies a component, and every control inside a block keeps its own eight states from the component spec. Values are JAL Core tokens from `jal-ui-taste`. The "From:" line records where the block's grammar came from; it is provenance, never a choice.

**Combining.** A block is the layout layer of a section stack. It combines with any recipe from any source in `recipe-index.md` when JEV judges the layer fits (`ui.component_recipe` on product and marketing surfaces, `imm.recipe` on immersive ones, the layering protocol in `recipe-index.md` section 4). There is no fixed layer limit. JAL law and the mechanical checks decide first and are never asked; a JEV yes cannot unlock a banned pattern.

## 0. How to read a block spec

Every block below carries the same fields:

- **Job and message:** what the visitor must understand or do after the block, and the one sentence it says. Write it as the section concept line (`jal-ui-taste` Section concept law) before markup; a block with no job is deleted.
- **Anatomy:** parts in reading order, each mapped to a component spec or a type role.
- **Container:** the rung on the Astryx ladder (`foundations.md` section 1): spacing, then divider, then section, then card. Take the lightest rung that still groups. JEV confirms it in `ui.region_gate`.
- **Tokens:** the JAL Core tokens the block reads. Nothing outside the `jal-ui-taste` tables.
- **Responsive (320 to 1280):** the per-region contract (divide, reveal, resize, swap) at 320 to 639 (app-shell), 640 to 1023, and 1024 to 1280 (content cap; above it the page centers and extra room goes to fill regions only).
- **States:** block-level states. Component states come from `components.md`.
- **A11y:** landmarks, names, keyboard, announcements beyond the component specs.
- **Motion by tier:** what each `motion.intensity` tier allows (0 still, 1 quiet, 2 staged, 3 cinematic). Prechecks that never reach JEV: product UI is capped at tier 1; pricing tables, forms, docs, and legal are tier 0; one tier-3 section per page. Reduced motion always collapses to the static final state with feedback kept at `--dur-reduced` or less.
- **Recipes:** candidate IDs from `recipe-index.md` sections 1 and 3, grouped by role. Precheck them against the Surf, Tier, Cost, Mobile, and Law columns before any JEV call.
- **Anti-patterns:** the `craft.md` bans that hit this block most often. The whole ban list still applies.
- **From:** the sources (Astryx, Carbon, Material, impeccable, hallmark, refero). hallmark items keep their `hm.` IDs.

Shared rules for every block:

- Section rhythm is one repeated value down the page (`--space-64px` to `--space-96px`), tight inside a group (`--space-8px` to `--space-16px`), generous between groups (`--space-32px` to `--space-48px`) (`craft.md` section 7).
- Heading rhythm: more space above a heading than below, 2x as the target (`craft.md` section 2).
- At most two text tiers per block: a lead line and one supporting line or body.
- Adjacent blocks differ in structure (container, column count, alignment, or density).
- One alignment (start or center) per page; asymmetry comes from spans, never overlap.
- Every block that shows data has an empty, loading, and error design (section 11).
- Nothing invented: every metric, quote, logo, customer, and price is real or a labeled placeholder (`hm.placeholder_honesty`, section 4).

## 1. KPI tile and KPI row

- **Job and message:** tell an operator the state of a few numbers that decide their next action, in one glance, and where to go when one is off. Message: "these are the numbers that matter today, and this one moved".
- **Anatomy (tile):** value (`--text-3` 28 / 36, weight 600, `ink`, tabular numerals, unit after a non-breaking space in `ink-muted` at the same step or `--text-0`) > label under the value (`--text-n1` 13 / 20, 400, `ink-muted`, names the metric and its scope: "Orders today") > optional delta row (direction icon 16 from koboyo, signed value, comparison period: "+4.2% vs last Monday", `--text-n1`) > optional sparkline (section 2, real data only) > optional trailing action (a link "View orders", or the whole tile as a ClickableCard). **KPI row:** 2 to 4 tiles of one shape, optional row heading (`--text-2`) and one period control (Segmented button: Today, 7 days, 30 days) that drives every tile together.
- **Container:** spacing first: a grid of tiles separated by gap alone, sitting on the page or inside one Bento tile, no box per tile. Step up to a card per tile (`surface` + 1px `border`, `--radius-12`) only when each tile is its own drill-in target or carries its own control. Never a card inside a card, never right-only cell borders between tiles (side lines, `hm.logo_wall` logic).
- **Tokens:** `--text-3` and `--line-3` (value; `--text-2` in a 4-up desktop row with long values), `--text-n1`, `--color-ink`, `--color-ink-muted`, `--color-success` or `--color-danger` on the delta only when the metric defines good and bad, `--space-4px` value to label, `--space-8px` label to delta, tile padding `--space-16px` (24 at 768 and up, minus the 1px border when carded), grid gap `--space-16px` (24 at 768 and up), `--radius-12`, `--color-layer-2` for skeleton blocks.
- **Responsive:** 320 to 639: two tracks of `minmax(0, 1fr)` when every value fits a track at 320 (about 8 characters), otherwise one column; never a horizontal scroll strip of tiles. 640 to 1023: two columns (a 3-tile row becomes 2 + 1 only if the third tile spans both tracks; otherwise drop to one per row). 1024 to 1280: 3 or 4 columns, equal heights (`grid-auto-rows: 1fr`), delta and action rows on one baseline (`margin-top: auto`). Values ellipsize never; a value that does not fit steps to `--text-2` for the whole row.
- **States:** loading = skeleton blocks at the value and label shapes after `--wait-skeleton`; no data = the value slot reads "No data" in `ink-muted` with the reason ("No orders yet today"), never a fake 0; error = "Unavailable" plus a retry icon button in the tile, or one inline Notification above the row when every tile failed; stale = meta line "Updated 12 min ago"; live = the value updates in place (`an.R08`), announcing only the final value; no permission = "No access" with who grants it; clickable tile = the ClickableCard hover 8%, focus ring around the whole tile, active 12%.
- **A11y:** each tile is a group labelled by its metric; the delta is read as words ("up 4.2 percent versus last Monday"), never as color or arrow alone; live values use `aria-live="polite"` with the final formatted value only (`hm.number_live`); numbers formatted with `Intl.NumberFormat`; the period control is a labelled Segmented button.
- **Motion by tier:** 0: static values, state layers only. 1 (product ceiling): one `mu.R01` product-preset entrance for the row, played once; live value changes use `an.R08`; value updates never count up (`ui.number_motion`: product KPIs are `static`). 2 and 3 do not apply on product UI. Reduced motion: final values at once, instant digit swap.
- **Recipes:** layout `core.bento`, `core.card`, `core.rows`, `core.tpl.dashboard`, `rf.D2.ledger_numbers`, `rf.D13.precision_dark` (explicit dark brief only); motion `mu.R01` (product preset); hover `core.clickable_card`; control-bound `an.R08` (live), `an.R36` (meter update), `an.R37` (activity grid), `core.badge`, `core.skeleton`, `core.segmented`. On a marketing stats section, `mu.R07` count-up is a candidate at tier 2 only.
- **Anti-patterns:** big-number hero or giant colored numerals (a KPI never exceeds `--text-3` in product UI, never at a display step); accent-colored values; sparklines or rings standing in for data; icon tile above the value; status by color alone; more than 4 tiles in a row (cognitive load, `craft.md` section 9); tiles of mixed shape.
- **From:** Astryx (hierarchy by weight and ink, dashboard template family), Carbon (data density, tabular numerals), Material (state layer on the clickable tile), impeccable (big-number ban, cognitive load), hallmark (`hm.number_live`, `hm.logo_wall` separation logic), refero (D2 ledger numbers).

## 2. Charts (line, bar, area, sparkline, donut)

The chart grammar under JAL law. Every chart is data first: a real data set, a stated takeaway, and a table of the same numbers.

- **Job and message:** show one relationship in the data (trend, comparison, part of a whole) so the reader can act. The message is written as the chart's title or summary sentence ("Revenue rose 12% from July to September"), never "Revenue chart".
- **Anatomy:** header (title `--text-1` 19 / 28, 600; one supporting line with the takeaway or scope, `--text-n1` `ink-muted`; trailing controls: period Segmented button, a Chart and Table Segmented button, overflow icon button) > plot (axes, gridlines, marks, direct labels) > legend (only when direct labels cannot work) > footnote (source and date, `--text-n1` `ink-muted`) > the data table (visible behind the Table segment, or directly below on mobile).
- **Chart types and when:**
  - **Line:** a trend over continuous time, up to 4 series. Stroke `--space-2px` (2), round joins, no markers at rest. A non-zero baseline is allowed only when the axis labels it.
  - **Bar:** comparison across categories or discrete periods. Baseline always at zero. Vertical for periods, horizontal when category labels are long or there are more than about 7 categories. Bar ends take `--radius-4` on the value end only, square at the baseline, or square everywhere; one choice per product. Bar gap at least 25% of the bar width. Grouped bars 2 to 3 per group; beyond that, small multiples.
  - **Area:** a single series' volume over time, or a stacked total with 2 to 3 parts. Fill is one flat opaque color mixed from the series stroke (`color-mix(in oklab, var(--series) 12%, var(--color-surface))`), never translucent overlapping areas, never a fill that fades.
  - **Sparkline:** a trend cue inside a KPI tile or a table cell, real data only. No axes, no tooltip, no end-point dot, stroke 2, block size `--space-32px`, fills its track. The number it belongs to is always in text beside it; the sparkline is `aria-hidden` when that text carries the meaning, otherwise `role="img"` with the trend as its name.
  - **Donut:** part of a whole with 2 to 4 parts that sum to a meaningful total; anything else is a bar. Ring stroke 12 at a 160 diameter (structural size), a 2 `surface` gap between segments, segments from the series ramp, the total in the center (`--text-2`, tabular) with its label (`--text-n1`); a row list beside or below gives each part's label, value, and percent. No pie, no 3D, no exploded slices, never more than 4 parts.
- **Categorical palette (ruled by the lead, 2026-09-29):** inside a data visualization only, series may use `--viz-1` to `--viz-6` (blue, teal, amber, green, red, slate; never the purple family; each at least 3:1 on `surface`), in that order, with dashes or markers as the second cue. JEV `ui.component_recipe` picks the categorical palette when series are nominal and 3 or more need telling apart at a glance, and the lightness ramp below when the chart is calm or ordinal. UI chrome around the chart keeps the one-accent rule.
- **Series ramp (color by lightness, then shape):** series 1 `--color-ink`, 2 `--color-ink-muted`, 3 `--color-ink-subtle`, 4 `--color-border-control`; each clears 3:1 on `surface` (17.2, 9.3, 5.3, 3.28) as WCAG 1.4.11 requires for graphics. Lines also differ by dash (solid, 8 4, 4 4, 2 4) so the ramp survives grayscale and forced colors. When the direction contract sets the accent to `signal_only`, the one key series stroke and its value label may take `--color-accent` and nothing else in the chart does. Status colors appear only for a real threshold breach, always with a label. More than 4 series means small multiples or a table, never more hues. Heat grids use the one-hue tonal ramp of `an.R37`.
- **Axes and grid:** tick labels `--text-n1` `ink-muted`, tabular numerals, 3 to 5 ticks on the value axis, `Intl.NumberFormat` with compact notation for large values and the unit in the axis title or after a non-breaking space; horizontal value gridlines 1px `--color-border` (functional); the zero baseline 1px `--color-border-strong`; no vertical gridlines by default; no chart border inside a card (the card owns the edge).
- **Legend:** direct labels at the line end or on the bar first (label in the series color only when that color passes 4.5:1 as text, otherwise `ink` with the key beside it). A separate legend sits above the plot, start-aligned: each key is a line segment in the series stroke and dash (16 by 2) for lines, a 12 by 12 `--radius-4` swatch for bars and areas. A key is a data encoding, never a decorative dot, and never a circle. Interactive legends are filter Chips (44, `aria-pressed`) that show or hide a series.
- **Tooltip:** on pointer hover or keyboard focus of an x position: a 1px `--color-border-strong` guide at that x (shown only while reading, not a connector), and a plain Tooltip chrome readout (`surface` + 1px `border-strong`, `--radius-8`, `--text-n1`, tabular) listing the x label and each series value with its key. It sits above the plot and flips below, never covering the hovered point; pointer delay follows `hm.tooltip_timing` (0ms on keyboard focus). Touch: tap selects an x position and pins the readout in a row above the plot; no hover dependency.
- **Accessible data table:** every chart ships a real `<table>` of the same numbers (DataTable chrome, caption naming the chart, header cells with scope, numbers right-aligned and tabular). The plot SVG is `role="img"` with `aria-labelledby` pointing to the title and the summary sentence. Keyboard: the plot is one tab stop; Left and Right move between x positions, Up and Down between series, Home and End jump; the readout follows focus and the focused value is announced politely.
- **Container:** a chart with its own controls is a card (`surface` + 1px `border`, `--radius-12`, the doctrine's "single chart with its own controls"); inside a dashboard it is a Bento tile. Charts fill their region width; only the plot body may `flex: 1` to fill tile height. A tall chart beside short lists goes in its own full-width band (`jal-ui-taste` Card and grid consistency).
- **Tokens:** the series ramp above, `--color-border`, `--color-border-strong`, `--color-accent` (signal_only only), status tokens (threshold only), `--text-1`, `--text-n1`, `--space-2px` stroke, `--space-16px` header to plot, `--space-8px` inside the header, `--radius-4` bar ends, `--radius-8` readout, `--radius-12` card, `--color-layer-2` skeleton.
- **Responsive:** plot block size is a structural budget: 192 below 640, 240 at 640, 320 at 1024 and up (sparkline 32 everywhere). 320 to 639: fills the width with the 16 gutter; value ticks drop to 3; direct labels become a legend row above; time series aggregate to fewer points (weeks, not days) rather than scroll; vertical bars with long labels swap to horizontal; the readout is tap-pinned; the Table segment stays available and the table stacks per the DataTable contract. 640 to 1023: full header controls; two charts per row only when each keeps 288 of plot width. 1024 to 1280: charts fill their Bento spans; no chart ever scrolls the page horizontally.
- **States:** loading = a skeleton of the plot area (axis stubs and a flat `layer-2` block) after `--wait-skeleton`, header visible; empty = EmptyState inside the plot area naming which empty ("No sales in this period") with one action (widen the period); partial data = gaps drawn as gaps (never interpolated) with a footnote; error = inline Notification in the card with retry, the header stays; stale = footnote "Data as of 09:40"; selected point = the guide plus the readout, the rest of the series unchanged (no dimming below 3:1); filtered = the legend chips show which series are hidden.
- **A11y:** summary sentence plus data table is the non-visual path; never color alone (ramp plus dash plus labels); every interactive part at 44 (chips, segments, overflow); forced-colors mode keeps strokes (use `CanvasText`) and dashes; respect RTL by mirroring the time axis only when the product's locale reads time right to left.
- **Motion by tier:** 0: static, value updates instant. 1 (product ceiling): `an.R36` entrance as opacity only (`--dur-200`), bar value updates by `transform: scaleY` or `scaleX` at `--dur-200`; lines and areas update instantly (path morphs are not transform or opacity). 2 (marketing only): `an.R36` showcase entrance (`--dur-400`), bars grow by transform from the baseline, staggered 30 to 50ms per bar with a 300ms total cap; donuts fade in (a sweep needs the two-half-ring transform build in `an.R36`). 3: not used for charts. Never animate width, height, or stroke-dashoffset; no line draw-on. Reduced motion: final state, no transition.
- **Recipes:** layout `core.card`, `core.bento`, `core.table` (the data table), `core.tpl.dashboard`, `rf.D2.ledger_numbers`, `rf.D3.spec_rows`; motion `an.R36`, `mu.R01`; static data viz `an.R37` (heat grid), `mu.R38` (dotted map); control-bound `core.segmented`, `core.chips`, `core.tooltip`, `core.skeleton`, `core.empty_state`, `core.notification`. On immersive surfaces only, `three.instanced_field` and `mu.R44` or `three.dot_globe` for geographic data after `ui.geo_visual`.
- **Anti-patterns:** gradient area fills, glow or halo on the hovered point, drop shadows on bars or readouts, neon series, 3D charts, rainbow scales and unpicked multi-hue palettes (the JEV-picked `--viz-*` palette is fine), purple-family series; truncated bar baselines; dual value axes; pie with more than 4 slices; decorative sparklines without data; chart junk (background grids beyond value lines, borders around the plot inside a card); a legend of bare dots; a chart with no table.
- **From:** Astryx (dashboard family, hierarchy), Carbon (data density, table as the accessible twin, tabular numerals), Material (tooltip chrome and timing, chip filters, state layers), impeccable (sparkline ban unless real, color never the only code), hallmark (`hm.number_live`, `hm.tooltip_timing`, `hm.decorative_a11y`), refero (D2 and D3 data grammars).

## 3. Pricing (tiers, billing toggle, comparison table)

- **Job and message:** let a buyer find their tier, see the real price, and start. Message: "this is what it costs and what you get".
- **Anatomy:** section heading (`--text-4` on a pricing page, `--text-3` as a landing section) and one supporting line > billing toggle (Segmented button, "Monthly" and "Yearly"; the saving appears in the segment label only when it is true: "Yearly, save 16%") > tier set: 2 to 4 tiers, each with name (`--text-1`, 600) and an inline Badge on the name row for the recommended tier ("Recommended"; "Most popular" only when data proves it), one line on who it is for (`ink-muted`), price (`--text-4` 33 / 40, 600, tabular, currency from `Intl.NumberFormat`, period suffix "/ month" in `ink-muted` at `--text-0`), billing note ("Billed yearly at Rp 1.200.000"), one CTA (primary on the recommended tier only, outlined on the others), feature list (rows: check icon 20 + 16 / 24 text, one fixed gap, "Everything in Starter, plus" as the first row on higher tiers) > comparison table (optional, for 8 or more differing features) > the terms line (tax, currency, trial, cancellation) > an FAQ block (section 7) when the buyer has real questions.
- **Container:** tiers are cards in one row (`surface` + 1px `border`, `--radius-12`), equal heights, the CTA directly under the price so it sits on one baseline across the row; in a plan picker inside checkout the tiers are SelectableCards (radio semantics, ring plus check when selected). The comparison is a DataTable, never cards. The section itself is plain spacing.
- **Tokens:** `--text-4`, `--text-1`, `--text-0`, `--text-n1`, `--color-ink`, `--color-ink-muted`, `--color-primary` (the one filled CTA), `--color-border`, `--color-layer-1` (feature group header rows in the table), `--radius-12`, `--radius-8`, card padding `--space-24px` at 768 and up, `--space-16px` below, tier gap `--space-16px` (24 at 1024).
- **Responsive:** 320 to 639: tiers stack in one column in the order the buyer most likely needs (recommended first only if the brief says so, otherwise ascending), the billing toggle fills the width, CTAs fill their card; the comparison table becomes a tier switcher (Segmented button for 3 or fewer tiers, Select for 4) above feature rows for the chosen tier, feature groups as headings; the page never scrolls sideways. 640 to 1023: two columns (a 3-tier set is 2 + 1 only when the third spans; otherwise one column of full-width cards); the comparison shows priority tiers with the rest reachable through the switcher. 1024 to 1280: all tiers in one row (3 or 4 columns), comparison table with a sticky header row of tier names and CTAs and a sticky first column with a 1px hairline edge.
- **States:** billing switched = prices update in place (odometer `an.R08` if the region allows, otherwise instant), width reserved so cards never reflow; loading price (regional pricing lookup) = skeleton on the price only; error = inline Notification with retry, the tiers stay readable with "Price unavailable"; current plan (signed-in upgrade page) = that tier's CTA becomes a disabled-looking "Current plan" text with the reason reachable, not a button; unavailable tier in the region = soft-disabled CTA with the reason; CTA states from Button.
- **A11y:** tiers are a list (`<ul>`), each a group labelled by its name; price read with its period ("Rp 99.000 per month"); the billing toggle is a labelled radio group; the comparison table has a caption, `scope` on tier and feature headers, and "Included" or "Not included" as text (visible or visually hidden) behind every icon; never a typed glyph for yes or no.
- **Motion by tier:** 0 always (pricing tables are tier 0 by precheck): state layers, the Segmented indicator (`an.R13`), and `an.R08` price swap, which are state-class recipes. A pricing section on a landing page may take a tier 1 `mu.R01` entrance for the section as a whole. Never a hover lift or a scaled "featured" card. Reduced motion: indicator jumps, prices swap instantly.
- **Recipes:** layout `core.selectable_card`, `core.card`, `core.table`, `rf.D2.ledger_numbers`; text `an.R08`; motion `mu.R01`; hover `mu.R15` (CTA); control-bound `an.R13`, `core.segmented`, `an.R14` (CTA status), `core.badge`, `core.select`.
- **Anti-patterns:** "Contact sales" on every tier (`hm.saas_voice`); fake strike-through prices or invented discounts; a colored top bar, raised card, scale, or glow on the recommended tier (emphasis is position, the one filled CTA, and the inline badge); a pill badge stacked above the tier name (the eyebrow pattern); ragged cards with CTAs at different heights; typed check or cross glyphs; hover lift plus shadow; the comparison built as cards.
- **From:** Carbon (DataTable comparison, sticky header), Astryx (card family, selectable tile), Material (Segmented button, state layers), impeccable (honest copy, no invented claims), hallmark (`hm.saas_voice` real price rule, `hm.one_hover_signal`), refero (D2 ledger numbers).

## 4. Testimonial and proof (quotes, logos, case metrics)

- **Job and message:** let a real customer say what changed for them, specifically, so the buyer believes the claim. Message: "someone like you got this outcome".
- **Anatomy:** **quote:** the quote text (one featured quote at `--text-2`; quotes in a set at `--text-0`), curly quotes, one specific outcome inside it > attribution: name (16 / 500 `ink`), role and company (13 `ink-muted`), optional avatar 40 (a real photo with consent), optional company logo in single ink > optional link to the full case. **Logo wall:** real customer logos only, one monochrome treatment, heights 32 to 48 with gutters 2 to 3 times that height, optional one-line caption naming what the logos mean ("Used by 40 cooperatives in Central Java"). **Case metric:** the number in `ink` at `--text-3`, its label under it (`ink-muted`), the customer and the date or source ("Koperasi Sido Makmur, March 2026"), linked to the case.
- **Never fabricated:** every quote, logo, name, avatar, and metric has a source recorded in the build report (who said it, where, the permission). A block with no real proof is deleted, not filled. **Placeholders are labeled:** while real proof is pending, the block renders an honest placeholder, routed through one constant with a TODO comment (`hm.placeholder_honesty`): a Badge "Sample" in the attribution row, bracketed placeholder text ("[Customer quote pending approval]"), never a plausible invented quote; logo placeholders are fixed-ratio boxes reading "Logo pending"; placeholder names follow `hm.placeholder_names` (plausible local names, never "Jane Doe" or Acme). A page with a placeholder constant still in use does not ship.
- **Container:** one featured quote is plain spacing (the Quote-Led shape when it opens the page); several quotes are rows in a divided section, or a Bento of unequal tiles when each carries a different kind of proof (quote, metric, logo set); a quote on a tonal `layer-1` surface with a full 1px hairline is allowed; never a left rule, never cards in cards. The logo wall is a grid separated by gap alone.
- **Tokens:** `--text-2`, `--text-3`, `--text-0`, `--text-n1`, `--color-ink`, `--color-ink-muted`, `--color-layer-1`, `--color-border`, `--radius-12` (tiles), `--radius-pill` (avatars), gaps from the section rhythm.
- **Responsive:** 320 to 639: one column; a quote set becomes a stack of rows (or an `an.R43` swipe carousel with 44 previous and next controls when there are more than 3); logo wall wraps to 2 or 3 per row at the same logo height; case metrics stack. 640 to 1023: two columns of quotes or metrics. 1024 to 1280: up to three columns, or a featured quote beside two supporting items (Split Studio grammar); logo wall in one or two rows.
- **States:** avatar or logo loading = a fixed-ratio `layer-2` block; image failed = initials avatar (text, `layer-2`) or the company name as text; carousel = current item announced, controls disabled at the ends (soft-disabled with a reason, or wrapping); marquee = paused on hover, focus, and the pause control.
- **A11y:** quotes use `<figure>` with `<blockquote>` and `<figcaption>`; logos are images with the company name as alt text, or `aria-hidden` when the caption lists them; a marquee has a visible pause control, pauses on focus, and exposes the full list statically to assistive tech.
- **Motion by tier:** 0: static. 1: one `mu.R01` entrance for the block. 2: `an.R02` per-word crossfade on the featured quote, or `an.R32` card deck (one testimonial at a time). 3: `mu.R18` quote or logo marquee, only when the items exceed the viewport width, with a pause control, and only if the page has no other tier-3 section. Reduced motion: static wrapped rows, no drift.
- **Recipes:** layout `an.R41`, `core.card`, `core.rows`, `mu.R35` (avatar row, no overlapping stack), `rf.D8.generous_air`, `rf.D7.editorial_measure` (content products only); text `an.R02`; motion `an.R32`, `mu.R18`, `mu.R01`; control-bound `an.R43`, `core.badge`.
- **Anti-patterns:** invented testimonials, logos, user counts, or metrics; stock placeholder names and cliche brands; a quote with no role, company, or outcome; left-rule quotes; overlapping avatar stacks; giant numerals for case metrics; colorful logos in mixed treatments; a logo wall of companies that are not customers; auto-scrolling marquee as filler; star ratings as typed glyphs.
- **From:** Astryx (hierarchy, card family), Material (state layers on carousel controls), impeccable (no invented claims, big-number ban, marquee rule), hallmark (`hm.logo_wall`, `hm.saas_voice`, `hm.placeholder_honesty`, `hm.placeholder_names`, Quote-Led shape), refero (D7 and D8 grammars).

## 5. Hero (every lawful variant)

A hero exists only on Persuade and Experience surfaces (`craft.md` section 1). Operate and Read screens open on a page header (title `--text-4` or `--text-5`, one supporting line, the primary action), never a hero.

- **Job and message:** the first viewport is a thesis, not a header (`craft.md` section 7): show what the product does at the scale it has in life, and make the one primary action obvious. Message: one idea the visitor could repeat an hour later (the memory test).
- **Anatomy (all variants):** headline (the one display element on the page) > one supporting line (`--text-1` or `--text-0`, `ink-muted`) > primary action (Button primary) and at most one secondary (outlined or ghost) > the variant's proof or media part > nothing else. No eyebrow, no pill, no kicker, no badge row above the headline.
- **Hero rules (hallmark, merged):** `hm.headline_buckets`: count the rendered headline characters; 21 to 50 may take the full display step the mode allows, 51 to 90 caps one step lower, over 90 is rewritten or capped at `--text-6`. `hm.hero_space`: the hero fills 70 to 90% of the first viewport, never `min-height: 100vh` or `100dvh`, bottom padding at least 1.3 times top padding. `hm.image_need`: typography-only is always acceptable; commerce, food, team, travel, and news need real photography; API, docs, CLI, and editorial get none; a vague brief defaults to none. `hm.survives_deletion`: delete the media and the hero must still stand on its type. `hm.video_lcp`: the LCP element is never lazy and gets `fetchpriority="high"`; autoplay only muted, looped, inline, with a poster.

## 11. Page states (empty, loading, error)

Whole-screen states inside the shell. The header and navigation always render; only the content region changes. Region-level states inside a block follow the same rules at region scale.

- **Job and message:** say what is happening, why, and the one next step, so no screen is ever blank or a dead end.
- **Empty (name which of the five):** first use, user cleared, no results, no permission, error (`craft.md` section 9). **Anatomy:** icon (24, koboyo, never an icon tile or an illustration made from shapes) > title (`--text-2`, names the state: "No invoices yet") > one sentence (what goes here and why it matters) > one primary action ("Create invoice") and at most one secondary link ("Import from spreadsheet"). No results adds the query and a clear-filters action; no permission names who grants access and offers "Request access"; first use may offer labeled sample data.
- **Loading:** the shell renders at once; the content region shows skeletons matching the expected layout exactly, only after `--wait-skeleton` (300ms), so fast loads never flash. Loading tiers (`hm.loading_tiers`): under 2s the skeleton alone; over 2s add the named operation ("Importing 240 invoices"); over 10s add real progress (linear Progress pinned under the header) and an honest estimate. Route changes may show page-level linear progress at the top of the content region, never under the tab bar. Never a full-screen spinner, never fake progress.
- **Error:** **Anatomy:** danger icon (24) > title naming what failed ("Orders could not load") > one sentence on why, when it helps, and the recovery > primary action (Retry) and one secondary (go back, or contact support) > optional reference code in `--text-n1` `ink-muted` for support, never as the main message. **By cause:** offline = a Banner under the header plus cached content marked stale; 401 = session expired, "Sign in again", the unsaved work kept; 403 = the no-permission empty state; 404 = "This page does not exist" with search and the home destination; 429 = "Too many requests, try again in 30 seconds" with the wait shown; 500 and timeouts = retry with the reason; partial failure = an inline Notification in the failed region only, the rest renders.
- **Container:** the state fills its region (EmptyState fills so the region never collapses), plain spacing, aligned with the page's alignment; in a master-detail layout the empty detail panel shows the empty state for "Nothing selected".
- **Tokens:** `--text-2`, `--text-0`, `--text-n1`, `--color-ink`, `--color-ink-muted`, `--color-danger` (icon only, plus the word in the title), `--color-danger-surface` and `--color-danger-border` (inline Notification chrome), `--color-layer-2` (skeleton blocks), `--wait-skeleton`, `--space-16px` icon to title, `--space-8px` title to sentence, `--space-24px` sentence to action.
- **Responsive:** 320 to 639: centered in the content region between header and tab bar, the action fills the width, the secondary link below. 640 to 1023 and 1024 to 1280: the state block caps near 480 of width inside its region and follows the page alignment; the skeleton follows each region's own responsive contract so nothing shifts when content arrives.
- **States:** loading to content without layout shift; retrying (the Retry button shows its loading state, width locked); retry failed again (the message updates with a support path, never the same text again); restored (content replaces the state silently).
- **A11y:** the content region sets `aria-busy="true"` while loading; start and completion are announced once through a polite live region ("Loading orders", "Orders loaded"), never every tick; errors that block the task use `role="alert"`; focus moves to the error title only when the error replaced the content the user was acting on; skeletons are `aria-hidden`.
- **Motion by tier:** 0: instant swaps; the skeleton opacity pulse (`an.R40`) stops under reduced motion. 1: one `mu.R01` product-preset entrance for an empty state. `an.R24` split-reveal preloader only on an immersive first load. Reduced motion: static skeleton blocks, a static "Loading" label, crossfade to content at `--dur-reduced` or less.
- **Recipes:** layout `core.empty_state`, `core.skeleton`, `rf.D1.type_led`; motion `mu.R01` (product preset), `an.R24` (immersive first load only); control-bound `an.R40`, `an.R39`, `an.R14`, `core.notification`, `core.banner`, `core.button`.
- **Anti-patterns:** blank screens; a bare spinner with no context; "Oops", "Uh oh", or "Something went wrong" as the whole message; humor on a failure path; exclamation marks in errors; raw error codes as the headline; illustrations faked from CSS shapes or 3D objects in an empty state; skeletons that do not match the real layout; hiding the navigation on an error.
- **From:** Astryx (EmptyState, Skeleton, system state taxonomy), Carbon (inline and actionable notifications, table states), Material (Progress, loading on buttons), impeccable (five empty states, UX writing, harden matrix of HTTP statuses), hallmark (`hm.loading_tiers`, `hm.copy_bans`, `hm.silent_success`), refero (D1 type-led).

## 12. Auth (sign in, sign up)

- **Job and message:** get a person into the product fast and safely, and tell them exactly what to fix when they cannot. Message: "sign in to <Product>" or "create your account".
- **App-shell:** auth screens have nothing to navigate to yet, so the page opts out of the bottom tab bar with `data-jal-shell="none"` on `main` (`ui_audit` honors this for the `mobile-app-shell` rule). Every other rule still applies.
- **Provider sign-in buttons (ruled by the lead):** use each provider's official mark from its own brand assets (Google, GitHub, Microsoft, Apple), following that provider's button guidelines, at 44px, full border. This is the one exception to the koboyo and reicon icon sourcing, because provider brand rules require the official mark.
- **Anatomy, sign in:** wordmark > title (`--text-3`, "Sign in to Warung Kas") > email TextInput (`type="email"`, `autocomplete="username"`, `inputmode="email"`) > password PasswordInput (`autocomplete="current-password"`, reveal toggle with `aria-pressed`, "Forgot password?" link in the helper row) > optional "Keep me signed in" Checkbox > primary Button "Sign in" (full width) > alternatives when the product offers them: passkey, email link, provider sign-in as outlined Buttons with the provider's official mark, introduced by a plain text line ("Or sign in with"), never by lines drawn either side > footer line "New to Warung Kas? Create an account".
- **Anatomy, sign up:** title > name > email > password with its requirements listed before submit (each rule as text with a check icon that fills as it is met, no color alone) > consent Checkbox for terms and privacy, never preselected, links open in place > primary Button "Create account" > sign-in link. After submit, the verification state replaces the form: "Check your inbox at rina@koperasi.id", resend (with a visible cooldown), change email.
- **Container:** from 640, one card (the doctrine's sign-in panel: `surface` + 1px `border`, `--radius-12` or `--radius-16`, padding `--space-32px` minus the border), width budget 400, centered on `page`. Below 640, no card: the form sits on the page with the 16 gutter, under a header row holding the wordmark and a close or back action. The form caps at 400 at every width; nothing else competes on the screen.
- **Tokens:** `--text-3`, `--text-0`, `--text-n1`, `--control-h`, `--color-surface`, `--color-page`, `--color-border`, `--color-border-control`, `--color-primary`, `--color-danger` with its surface and border (the form-level notice), `--radius-12` or `--radius-16`, field gap `--space-16px`, title to first field `--space-24px`, action gap `--space-12px`.
- **Responsive:** 320 to 639: single column, full-width fields and buttons, the keyboard never covers the focused field (the content region scrolls, `scroll-padding`), provider buttons stack. 640 to 1023 and 1024 to 1280: the centered 400 card; an optional Split Studio variant from 1024 places a real product statement or proof column beside the card on marketing-grade sign-up pages only (never on sign in).
- **States:** fields validate on blur first, then live (`hm.touched_validation`); submit stays enabled while idle (`hm.submit_rule`) and blocks double submits while in flight (loading, width locked, `aria-busy`); wrong credentials = one form-level Notification above the fields, "Email or password is incorrect" (never which one, to avoid account enumeration), focus moves to it; format errors in each field's message row; caps lock on = a warning in the password helper row; locked or rate-limited (429) = the wait time and a recovery path; expired session return = a banner explaining why they are here; success = straight into the product (silent), or the verification state for sign up; offline = a Banner and the submit held with a retry.
- **A11y:** real labels above every field; `autocomplete` on every field so password managers work; paste always allowed; the reveal toggle has a stable name ("Show password") with `aria-pressed`; an error summary receives focus on a failed submit and links to each field; every target 44; never a custom CAPTCHA puzzle as the only path; one `<main>` with the form labelled by its title.
- **Motion by tier:** 0 always (forms are tier 0): state layers, the button loading state (`an.R14`), the verification state swapping in by opacity at `--dur-200`. Reduced motion: instant swap.
- **Recipes:** layout `core.tpl.login`, `core.plain_spacing`, `core.card`; control-bound `core.text_input`, `core.checkbox_radio`, `core.button` with `an.R14`, `core.notification`, `core.banner`.
- **Anti-patterns:** a hero or marketing sections around the sign-in form; floating labels or placeholder-only labels; disabling paste; "Submit" as the button label; revealing whether an email is registered; preselected consent; decorative "or" divider lines; dark or image-filled auth backgrounds; a password rule revealed only after failure.
- **From:** Astryx (login template family, card as a hard boundary), Carbon (form anatomy, inline notification), Material (field rules, input types, checkbox, button emphasis), impeccable (UX writing, harden matrix), hallmark (`hm.touched_validation`, `hm.submit_rule`, `hm.input_geometry`, `hm.copy_bans`).

## 13. Settings page layout

- **Job and message:** let a user find one setting fast, change it, and trust that it took. Message: the section's name and what it controls.
- **Anatomy:** settings navigation (sections: Profile, Notifications, Billing, Team, Security, and so on) > section header (title `--text-3`, one sentence on what the section controls) > setting groups (group heading `--text-1`, optional description) > setting rows: label (16 / 500), description (13 `ink-muted`), trailing control (Switch for settings that apply at once, Select or Segmented button for choices, current value plus chevron for a drill-in, a Button for an action) > form groups (profile fields) with their own Save action, shown when the group is dirty > the destructive zone last (heading naming the action, one sentence of consequence, destructive Button).
- **Container:** the page is a divided section; groups are separated by spacing and a 1px divider; rows are a List (records as rows) with dividers inset to the text start; no card per setting, no cards in cards. The settings navigation is a list inside the content region (not the product's primary nav). The destructive zone is its own group, optionally in the danger notice chrome (full four-side hairline, never a colored side).
- **Tokens:** `--text-3`, `--text-1`, `--text-0`, `--text-n1`, `--color-ink`, `--color-ink-muted`, `--color-border`, `--color-layer-2` (current section in the nav), `--color-danger` (destructive button and zone icon), density from `ui.density` (settings usually `comfortable`: row padding-block 16 at 1024 and up; 56 minimum row height below 1024), content column capped at 640, navigation width budget 240, gap between nav and content `--space-48px`.
- **Responsive:** 320 to 639: list-detail swap: the settings index is a list of section rows with chevrons; each section opens as its own screen with a back button in the app-shell header and the section title; trailing controls stay in their rows; a form group's Save pins above the tab bar only while the group is dirty. 640 to 1023: the index list stays a separate screen, or becomes Tabs across the top when there are 5 or fewer sections. 1024 to 1280: the settings nav beside the capped content column; a settings search field above the nav when there are more than about 20 settings.
- **States:** immediate settings save silently (the Switch itself is the confirmation, `hm.silent_success`), failures revert the control and say why in the row's hint; autosaved fields show a transient "Saved" in the hint row; a dirty form group shows its Save and Cancel, and leaving with unsaved changes asks "Discard changes?"; saving = row or group `aria-busy`; permission-locked settings are soft-disabled with the reason ("Only owners can change billing"); loading = skeleton rows of the same heights; section error = inline Notification with retry; destructive confirm = AlertDialog, and a truly irreversible action asks for the typed name (`hm.typed_confirm`), anything reversible offers undo instead.
- **A11y:** the settings nav is a `<nav aria-label="Settings">` with `aria-current` on the current section; each group is a `<section>` or `<fieldset>` labelled by its heading; every Switch uses `role="switch"` and is named by the setting, not the state; descriptions attach with `aria-describedby`; the dirty-state prompt is a labelled dialog; focus moves to the section heading after a section change.
- **Motion by tier:** 0 (the default): state layers, Switch handle travel (`an.R17`), Segmented indicator (`an.R13`). 1: none beyond state recipes; no entrances on settings. A toast (`core.notification`) only for an effect the user cannot see (an email sent, a sync elsewhere). Reduced motion: instant.
- **Recipes:** layout `core.divided_section`, `core.list`, `core.tpl.settings`, `core.master_detail` (list-detail swap); control-bound `core.switch` with `an.R17`, `core.select`, `core.segmented` with `an.R13`, `core.text_input`, `core.notification`, `core.dialog`, `core.alert_dialog`, `mu.R34` (explicit dark mode only).
- **Anti-patterns:** a card per setting; `justify-content: space-between` stretching rows to fill a card; a toast on every toggle; a checkbox for a setting that applies at once; a Switch labelled with its state ("Turn on"); a global Save for a page of mixed immediate and form settings; a red-bordered side stripe on the danger zone; destinations duplicated between the product nav and the settings nav.
- **From:** Astryx (settings template family, list anatomy, master-detail), Carbon (density, forms, notifications), Material (Switch, Select, Segmented button, list keyboard model, dialog return value), impeccable (undo over confirmation, cognitive load), hallmark (`hm.silent_success`, `hm.typed_confirm`, `hm.touched_validation`), refero (D5 calm productivity grammar).
