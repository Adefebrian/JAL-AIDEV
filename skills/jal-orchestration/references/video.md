# Playbook: Video and Remotion sections

Internal playbook, run through the `jal-orchestration` engine by `/jal-build` or `/jal-ui` (see `../SKILL.md`). It runs for every video request (MP4, WebM, GIF, a social cut, a captioned clip) and for every page section whose `motion.engine` is `remotion`. Remotion is JAL's core motion engine (Brian, 2026-10-01); skill `jal-remotion` holds the rules, and the code is the opt-in video module (`templates/modules/video`, its README describes `RemotionSection`, the compositions registry, the in-browser export helper, and the optional Studio entry).

Request: <request>

## Steps, in order

1. **Intake.** Restate the deliverable: format, length in seconds, aspect (16:9, 9:16, 1:1, 4:5), fps, captions, audio, and where it will be used (a page section, a file, or both). A video request is `motion.engine` `remotion` by precheck, never asked. Check the license stop rule before any install: a 4th team member or an external client who would receive the source stops the run with the warning in `jal-remotion` SKILL section 6, and Brian decides.
2. **Engine and recipe.** On a page, `motion.intensity` then `motion.engine` per section (one batched call). For each Remotion section or file, `motion.remotion_recipe`: 3 to 8 candidates from at least 3 `rm` families in `jal-remotion` `references/visuals/recipe-index.md`, plus the module's registry compositions as the JAL-native base, then the `layer_n` growth. Supplements (kit motion, Lenis and GSAP, R3F, noyzzi and libraries) layer through the protocol in `jal-design-system` `references/recipe-index.md` section 4.
3. **Module.** If `packages/video` does not exist, copy `templates/modules/video` there (its README has the steps). `bun add --exact` every `remotion` and `@remotion/*` package on one version; Mediabunny pinned to Remotion's paired version. Never `@remotion/media-parser` or `@remotion/webcodecs`. Studio, its bundler, and the CLI only inside the video workspace; `apps/web` stays on `Bun.build` with the Player in a lazy split chunk. Paid items, ElevenLabs, the OpenAI Whisper API, transformers.js, and `remotion skills add` stay off unless Brian said yes for this project.
4. **Render path.** For any file, `video.render_path`. `web_renderer` (`renderMediaOnWeb`, WebCodecs, `licenseKey: 'free-license'`) needs no question when a person is at a screen and the fit check passes. Any other path (local CLI, a Coolify render service, Lambda, Cloud Run, Vercel) stops here: `orch.escalate`, ask Brian with the confirmation wording in `jal-remotion` `references/rendering/render-paths.md`, and continue only after his yes, recorded with the `adr` playbook.
5. **Plan and build.** Ownership: the composition files and the page section go to the UI owner (jal-ux, jal-immersive for a 3D composition, or jal-frontend); an export feature inside a product goes to jal-frontend, with jal-backend only when a server is involved (and then only after step 4's yes). Each brief names skill `jal-remotion` and the catalog IDs for its role. On a page: `RemotionSection` inside the kit, poster first, `autoplay`, `scrub` (Lenis as the scroll source), or `manual`, custom controls from kit tokens. On a public page with an export: one privacy-policy line and no UI text, and `https://www.remotion.pro` in `connect-src`.
6. **Verify.**
   - Pages: `bun run build && bun test`, the bundle split (no Remotion code in the first chunk), `ui_audit` PASS at 320, 375, 414, 768, and 1280, `ui_shots` at 375 and 1280, the network log (the Player sends nothing), then the UI critic gate (`../SKILL.md` step 6b).
   - Files: `bun scripts/video/probe-mp4.ts <file>` (duration, size, codec, frames, fps, fast start match the brief), then the frame-sample check: at least five frames (first, 25, 50, and 75 percent, last, plus every scene cut) rendered with `renderStillOnWeb` or decoded with Mediabunny, each image Read against the law, legibility, safe areas, and captions.
7. **Report.** The deliverable and where it lives, every JEV decision (ID, answer, confidence, action), the `rm` stack per section with its source family, the render path and any confirmation Brian gave, the probe line and the sampled frame paths for a file, the `ui_audit` result per width and the critic scores for a page, and build and test status.

Stay terse, no narration beyond the report.
